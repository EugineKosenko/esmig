* Whitespaces

Parser ~ws~ (/W/-hite /S/-paces) matches any sequence of white spaces, which automatically wipes them
from the code. This is a wrapper around another parser.

#+begin_src rust :noweb yes :noweb-ref esmig:main:Definitions

  where
      F: NomParser<&'a str, Output = O, Error = E>,
      E: ParseError<&'a str>,
  {
      delimited(multispace0, inner, multispace0)

** String literals

String literal is just a sequence between double quotes. However, there is a nuance with escaped
characters (like the quote itself, =cr=, =lf=, =tab= and the escape character (backslash) itself). The
parser ~content~ processes these nuances.

#+begin_src rust :noweb yes :noweb-ref esmig:main:Declarations
  use nom::{
      bytes::complete::escaped_transform,
      character::complete::none_of
  };
#+end_src

#+begin_src rust :noweb yes :noweb-ref esmig:main:Definitions
  fn content(input: &str) -> IResult<&str, String> {
      escaped_transform(
          none_of("\"\\\n\r\t"), '\\',
          alt((
              value("\"", char('"')),
              value("\\", char('\\')),
              value("\n", char('n')),
              value("\r", char('r')),
              value("\t", char('t'))
          ))
      ).parse(input)
  }
#+end_src

Parsers ~str0~ and ~str1~ match empty and non-empty strings with delimiting quotes correspondently. Here
we wrap parsers in ~ws~ thus any string may have arbitrary whitespace delimiters.

#+begin_src rust :noweb yes :noweb-ref esmig:main:Declarations
  use nom::combinator::opt;
#+end_src

#+begin_src rust :noweb yes :noweb-ref esmig:main:Definitions
  fn str0(input: &str) -> IResult<&str, String> {
      ws(delimited(
          char('"'),
          map(opt(content), |s| s.unwrap_or_else(String::new)),
          char('"'))
      ).parse(input)
  }

  fn str1(input: &str) -> IResult<&str, String> {
      ws(delimited(char('"'), content, char('"'))).parse(input)
  }
#+end_src

*** Numbers

Here we have a specific moment that ~i128~ parser consumes integers till the floating point, but ~double~
parser consumes integers as floats. So we may not put the parsers in any order.

Therefore we try to parse doubles first, but if the next sequence contains floating point or exponent
sign.

#+begin_src rust :noweb yes :noweb-ref esmig:main:Declarations
  use nom::{
      bytes::complete::is_not,
      character::complete::i128,
      combinator::peek,
      number::complete::double
  };
#+end_src

#+begin_src rust :noweb yes :noweb-ref esmig:main:Definitions
  fn jnum(input: &str) -> IResult<&str, serde_json::Value> {
      let (_, ahead) = peek(is_not(" \t\n\r")).parse(input)?;
      if ahead.contains('.') || ahead.to_lowercase().contains('e') {
          map(double, |f| serde_json::Value::Number(serde_json::Number::from_f64(f).unwrap())).parse(input)
      } else {
          map(i128, |i| serde_json::Value::Number(serde_json::Number::from_i128(i).unwrap())).parse(input)
      }
  }
#+end_src

          .filter_map(|entry| entry.ok())
          .filter(|path| path.is_dir())
          .map(|path| path.file_name().unwrap().to_string_lossy().to_string())
          .next().unwrap();
      
      process_mgrtn(&mgrtn, "down").await;

      es.delete_by_query(DeleteByQueryParts::Index(&[&mgrtns_index_name]))
          .body(json!({ "query": { "match": { "version": version } } }))
          .send().await.unwrap();
